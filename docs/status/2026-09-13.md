## Summary

Img2Model AMD is a native Windows AMD image-to-3D desktop application built around Tauri/React, a persistent Python worker, Hunyuan3D-2 Mini for shape generation and Hunyuan Paint for optional texture generation.

The native ROCm/TheRock path is hardware-validated on a Radeon RX 6950 XT 16 GB (`gfx1030`) for both Shape and Hunyuan Paint. The current development focus is the new `mesh-cleanup-v2` game-ready asset pipeline and startup UX.

## Game-ready mesh cleanup v2

The original heuristic cleanup (`mesh-cleanup-v1`) was found to be ineffective on real Hunyuan output. A representative 534k-triangle steak changed by only one triangle, welded two vertices and detected zero spikes in Game-ready mode. That path is no longer considered sufficient for game-ready asset preparation.

`mesh-cleanup-v2` has now been implemented with:

- `Light` kept as a conservative, topology-preserving Trimesh path.
- `Game-ready` and `Aggressive` routed through PyMeshLab.
- Pinned `pymeshlab==2025.7.post1`.
- Pinned `manifold3d==3.5.3` for optional validation/finalization.
- Duplicate / null face cleanup.
- Duplicate vertex cleanup.
- Non-manifold vertex and edge repair.
- Small connected-component removal.
- Hole closing.
- Isotropic remeshing where configured.
- Adaptive QEM reduction.
- Symmetric Hausdorff error normalized by the mesh bounding-box diagonal.
- Automatic triangle-budget mode driven by geometric error.
- Manual triangle target override, defaulting to 5000 with a UI range of 500–500000 and step 500.
- Cache identity includes Auto/Manual mode and manual target.
- Algorithm version bumped to `mesh-cleanup-v2`, invalidating v1 cleanup cache entries.

For a simple prop such as the steak, the intended Game-ready result is in the low-thousands of triangles when geometric-error tolerance permits. This is deliberately not a fixed 5k rule: more complex models may retain more geometry.

## Windows runtime dependency probe fix

PyMeshLab and Manifold3D were correctly installed on the hardware runtime, but `windows-native-rocm.ps1` initially failed during dependency verification on Windows PowerShell 5.1.

Root cause: the probe used `python -c` with nested quoted Python strings. Windows PowerShell 5.1 changed the native argv quoting, causing `importlib.metadata.version()` to receive the imported module object instead of the package-name string.

The verification probe now uses a temporary `.py` file instead of `python -c`. A regression test prevents reintroducing this Windows quoting failure.

## Important limitations

- `mesh-cleanup-v2` has automated coverage and CI validation, but real RX 6950 XT Game-ready quality/performance acceptance is still pending.
- Manifold3D is a final validation/finalization aid, not a guaranteed repair path for arbitrary broken input.
- Hunyuan Paint remains much more memory-intensive than Shape and intentionally stays lazy-loaded.
- The current main GUI still appears before Shape preload finishes; splash/pre-main preload is the next startup UX task.
- WSL2 execution and Vulkan/TRELLIS remain future/experimental backends rather than silent fallbacks.
